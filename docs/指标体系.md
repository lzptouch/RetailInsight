# 指标体系

所有指标计算只在 `retailinsight/features/` 实现一次，notebook/看板/报表只调用。

## 1. 时间窗口径（两套，禁止混用）

| 分析 | 基准日 | 观察窗 | 性质 |
|---|---|---|---|
| EDA / RFM / 画像 | 数据最大交易日期 + 1 天（2022-08-01） | 全量 31 个月（2020-01 ~ 2022-07） | 描述性：现在谁是重要客户 |
| 流失预测 | 各 cohort 截止日（2021-04-01 / 2021-07-01 / 2021-10-01 / 2022-01-01 / 2022-04-01） | 270 天观察窗 + 90 天标签窗，滚动 **5 期**（训练 3 + 验证 1 + 测试 1） | 预测性：谁将会流失 |

## 2. 趋势分析口径（新增）

| 指标 | 口径 | 代码 |
|---|---|---|
| 环比（mom） | 本期 / 上一期 − 1（月度对上月、季度对上季度） | `reports/core_reports.py::add_growth_columns` |
| 同比（yoy） | 本期 / 上年同期 − 1（按月份/季度序号分组后 pct_change） | 同上 |
| 口径边界 | 数据为 31 个月非完整年度：1~7 月三年可比（2020/2021/2022），8~12 月两年可比（2020 vs 2021）；**2022Q3 仅含 7 月，为不完整季度，不参与同比解读** | — |

## 3. RFM 口径

| 指标 | 口径 | 代码 |
|---|---|---|
| R（recency_days） | 基准日 − 最近一次消费日（天） | `features/rfm.py::compute_rfm` |
| F（frequency） | 观察窗内消费天数，同日多单合并计 1 次 | 同上 |
| M（monetary） | 观察窗内净消费额（实付 − 退货） | 同上 |
| 分群 | R/F/M 五分位打分 1~5，≥4（前 40%）记「高」，2×2×2 映射 8 类客群 | `assign_segment` |

8 类客群：重要价值/重要发展/重要保持/重要挽留/一般价值/潜力/一般保持/流失风险。

## 4. 画像标签（P0 20 个）

基础属性（gender / age_band / city_tier / tenure_days / store_id）；
消费能力（avg_basket / monthly_amount / yearly_freq / discount_sensitivity / return_rate）；
行为偏好（active_band / weekend_ratio / top_categories / top_brands / category_entropy / items_per_txn）；
生命周期（rfm_segment / recency_days / frequency / monetary / value_tier）。
代码：`features/tags.py::build_profile`。

## 5. 流失标签

观察窗内活跃（≥1 笔）且标签窗内 0 交易 → churn=1。特征只用观察窗，标签只看标签窗，按时间切分训练/测试。代码：`models/churn.py::build_cohort_samples`。

## 5.5 CLV 口径（简化法，非 BG/NBD）

> **口径声明**：本项目实现的是**简化法**，不是 BG/NBD + Gamma-Gamma。
> 好处是每个输入都来自已有产物、可逐行追溯；代价是假设了「留存期服从几何分布」。

| 字段 | 公式 | 说明 |
|---|---|---|
| `monthly_churn_rate` | `1 - (1 - churn_prob) ^ (1/3)` | churn_prob 是 **90 天**标签窗的流失概率，除以 3 个月换算月流失率 |
| `expected_lifetime_months` | `1 / monthly_churn_rate` | 封顶 120 个月 |
| `clv` | `monthly_amount × expected_lifetime_months × 0.30` | **毛利率 0.30 是假设值**（零售常见区间 25%~35%），上线前需用甲方真实毛利校准 |
| `clv_tier` | `clv` 的四分位 | 低CLV / 中低CLV / 中高CLV / 高CLV |
| `clv_source` | `model` / `segment_median` | 未被流失模型覆盖的会员用**同客群中位留存月数**兜底并标注来源，不静默填 0 |

**覆盖率**：流失模型只覆盖末期观察窗内的活跃会员（22,777 / 36,000 = **63.3%**），
其余会员的 `clv` 走 `segment_median` 兜底路径，看板与画像卡片里均标注了来源。

## 5.8 P1 扩展标签口径（18 个）

| 标签 | 口径 |
|---|---|
| `promo_response_rate` | 有折扣订单数 / 全部订单数 |
| `coupon_used_rate` | 小额券（折扣额 ≤ 10 元）订单 / 全部有折扣订单 |
| `price_elasticity` | 有折扣订单的平均折扣额 / 该会员**中位**订单额（裁剪到 [0,1]） |
| `store_cnt` | 消费过的门店数（生成器已埋跨店购物行为） |
| `store_concentration` | 最大门店消费额占比 |
| `fresh_ratio` | 生鲜品类消费额占比（生鲜品类见 `io/schema.py::FRESH_CATEGORIES`） |
| `import_preference` | 进口商品消费额占比（商品表需有 `is_import` 字段） |
| `brand_loyalty` | 最大品牌消费额占比 |
| `new_product_rate` | 所购 SKU 中「全局首次成交日晚于该会员首单日」的件数占比 |
| `repurchase_cycle_days` | 相邻两次购买间隔（天）的中位数 |
| `interval_std` | 购买间隔的标准差 |
| `silence_ratio` | 距基准日天数 / 观察窗长度 |
| `cross_category_ratio` | 单次订单的平均品类数 / 该会员买过的品类总数 |
| `basket_structure` | 订单金额变异系数（分母用中位金额，裁剪上限 10） |
| `channel_preference` | 平均单次件数 / 该会员最大单次件数（**基于明细表**） |
| `price_band` | 客单价在全体会员中的分位 |
| `lifecycle_stage` | 序数编码 1 新客 / 2 成长 / 3 成熟 / 4 衰退 / 5 沉睡 |
| `potential_index` | `0.5×f分位 + 0.3×m分位 + 0.2×(1−r分位)`，贡献未起的（m 分位 < 0.6）加权 ×1.15 |

**共同纪律**：全部基于「会员且无逻辑错误」的交易；比率类分母加 `1e-9`；缺失填 0 而非 NaN。
**降级约定**：商品表缺 `is_import` / `category` / `brand` 时，对应标签显式降级为 0 并在 `attrs["degraded"]` 标注原因。

## 6. 模型验收

| 指标 | 定义 | 实测（主模型 RandomForest） | 对照（GBDT / LightGBM） |
|---|---|---|---|
| AUC | ROC 曲线下面积 | **0.8300**（LR 基线 0.7995，**+0.0305 达标**） | 0.8179（+0.0184 未达标） |
| KS | max(TPR−FPR) | **0.4936** | 0.4836 |
| Top20% 捕获率 | 名单前 20% 捕获的流失者占比 | **46.77%** | 47.00% |
| Lift@20% | Top20% 精确率 / 基线流失率 | **2.34**（基线 36.72%，理论上限 2.72，达上限 **86%**） | 2.35 |

注：Lift 上限 = 1/基线率；基线流失率 36.7% 时 lift≥3 数学上不可达，验收以「AUC 超基线 +0.03 + 接近上限」为准。

**主模型选型规则**（写死在 `models/churn.py::select_main_model`，不靠人工挑选）：
① 先筛出「AUC ≥ LR 基线 + 0.03」的达标组；② 达标组非空 → 取其中 **KS 最高**者；
③ 全不达标 → 取 AUC 最高者并标记未达标。当前达标组只有 RandomForest（KS 0.4936）→ 主模型为 RF。

> **口径纪律（v3.3 修正）**：决策建议报告等**所有对外披露**的模型指标一律取
> `metrics_churn.json::main_model_metrics`（主模型口径），
> 不得混用对照模型的指标 —— v3.2 曾出现「AUC 取 GBDT 的、增益取 RF 的」的混用，
> 导致报告里同时出现「已达标」与「无一达到 +0.03」两句矛盾的话（见计划 §0.9 缺陷 9）。
