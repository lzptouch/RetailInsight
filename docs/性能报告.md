## 四、结论

全部 12 个 stage 在该规模下均跑通，合计 12450.4s，峰值内存 7287.3 MB（约 7.12 GB）。

### 降级预案（按计划 §4.4 与 §12 风险 2）

1. **降 `--scale`**：把压测档降回 `1`（12 万会员 / 130 万交易 / 700 万明细），本机实测可在 8GB 内存内跑完全链路。
2. **分区裁剪**：明细已按 `txn_month` 分区，窗口期分析只加载所需分区（实测读 3 个月仅占全量 20.2%）。
3. **dtype 优化**：ID 降位 + 金额 float32 + 低基数字符串 category。
4. **聚合下沉 DuckDB**：星型模型已落地，可把大聚合改成 SQL 直读 parquet，避免 pandas 全表 join 峰值。
