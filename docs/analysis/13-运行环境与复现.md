# 运行环境与复现

> 对应域：D9（工程基础 · 运维腿）。对应 Kquery 的「13-部署与运维」。关键数字见 `README.md` 关键数字表。

## 〇、摘要

本项目的「部署」是**单机复现**：clone → venv → `make install` → `make all` → `make dashboard`。没有容器与服务编排，复杂性集中在**可选依赖的降级行为**与**平台相关的原生库**（libomp）。

## 一、环境要求

| 项 | 要求 |
|---|---|
| Python | ≥3.11（开发基线 3.13） |
| 包管理 | pip + venv（`uv.lock` 存在，`uv sync` 亦可） |
| 主依赖 | 12 项（pandas/numpy/pyarrow/matplotlib/openpyxl/scikit-learn/mlxtend/streamlit/**duckdb/plotly/shap/lifetimes**） |
| 可选 | `dev`（pytest/pytest-cov/ruff/psutil）、`lgbm`（lightgbm） |

> v3.4 决策：duckdb/plotly/shap/lifetimes 从「可选」提升为**主依赖**——它们是主链路必经，缺失时不是报错就是静默产出空列。只有 lightgbm 保持可选（降级路径成熟且指标损失可接受）。

## 二、复现步骤（根 README 快速开始）

```bash
python -m venv .venv && source .venv/bin/activate
make install                     # pip install -e ".[dev]"
python scripts/fix_lightgbm_dylib.py   # 仅 macOS 且 lightgbm 报 libomp 缺失时
make all                         # 14 个 stage，约 2.5 分钟
make test                        # 200 用例 + 覆盖率门禁 ≥60%
make dashboard                   # streamlit run dashboard/app.py（:8501）
python scripts/build_notebooks.py && jupyter lab notebooks/   # 5 个已执行 notebook
python scripts/exp_scale5.py --scale 5                        # 性能压测
```

## 三、平台坑位（实测）

| 坑 | 现象 | 解法 |
|---|---|---|
| macOS lightgbm 缺 libomp | import 即崩 | `scripts/fix_lightgbm_dylib.py` 自动修复；不修复则自动降级 HistGB 并留痕 |
| 依赖漏声明 | 链路中途崩 / 静默空列 | v3.4 已修；`tests/guards/test_import_smoke.py` 防回归 |
| 单文件跑测试被覆盖率判红 | `pytest tests/x.py` 必红 | 门禁只在 `make test`/`make cov` 全量生效（v3.6 修，见 `pyproject.toml` 注释） |
| os.path 兼容性（本机 macOS 环境） | 个别环境下 `os.path.X` 链式调用异常 | 全仓统一 **pathlib**（`settings.py` 头注释） |

## 四、产物目录与重置

- 运行产物：`data/`（raw/interim/marts + duckdb）、`reports/`（报告/图/json/xlsx）。
- 重置：`make clean`（缓存类）+ 手动删 `data/ reports/` 后重跑 `make all` 即全新基线。
- 多份产物对比：`RETAILINSIGHT_MARTS=/path/to/other/marts streamlit run dashboard/app.py`。

## 五、「运维」等价物

| 服务型系统 | 本项目 |
|---|---|
| 健康探针 | `make test` + import 冒烟 |
| 监控指标 | `reports/metrics_*.json`（churn/cluster/clv） |
| 告警 | CLI 降级警告（如 lifetimes 缺失打印，`cli.py:110`） |
| 备份/容灾 | git 管理代码与报告；data 可由 `make all` 确定性重建（seed=42） |
| 值班处置 | 复现步骤 §二；坑位表 §三 |

## 六、边界与已知缺口

1. 无 Docker 镜像与 CI 工作流（Makefile 即门禁入口；上 GitHub 可补 workflow，当前作品集规模未做）。
2. seed=42 保证同机确定性；跨平台（numpy/BLAS 差异）未做字节级一致性承诺。
3. `uv.lock` 与 `pip install -e` 双通道并存，锁文件 freshness 靠手工维护。

## 维护触发

新增依赖 → `pyproject.toml` + 评估是否走降级契约；新增平台坑 → §三表格。
