# 看板与交互体验

> 对应域：D8（交互体验）。对应 Kquery 的 D9（前端体验）。关键数字见 `README.md` 关键数字表。

## 〇、摘要

Streamlit 4 页看板，定位是**只读的交互式交付物**：数据源只读 `data/marts/`，不在看板里重算任何指标（口径单一真相源在 `retailinsight/features/`）。交互的亮点是 plotly 点选下钻——从 36,000 人的散点云直接钻到单个会员的完整画像。

## 一、页面结构（`dashboard/app.py`）

| 页 | 内容 | 主要产物 |
|---|---|---|
| 经营驾驶舱 | GMV 趋势、季节双峰、品类集中度、时段特征 | `mart_monthly` 等 |
| 客群分析 | RFM 8 群分布、**R×M 散点（气泡=频次）**、点选下钻 | `mart_rfm` + `mart_member_profile` |
| 商品洞察 | 关联规则筛选（support/confidence/lift）、品类结构 | `mart_basket_rules` |
| 流失预警 | 高危名单、概率分布、lift 曲线、单会员归因 | `mart_churn_score` + profile |

## 二、交互设计

- **plotly 散点（R × M，气泡 = 频次）**：hover 显示会员摘要；**点选下钻**：点击任意散点 → 右侧展示该会员完整画像 + 同客群对比。
- **客群筛选联动**：左侧筛选客群，散点与明细表同步过滤。
- 下钻的价值：把「18.3% 的人贡献 42.5% GMV」从统计结论变成**可逐个查看的具体会员**，答辩与业务沟通时说服力完全不同。

## 三、性能

- 首屏实测 **0.51s**（验收线 < 3s）。
- 机制：`@st.cache_data(ttl=3600)` 缓存 parquet 读取；首屏计时口径 = 「脚本开始到首屏渲染完成」（Streamlit 每次交互重跑脚本，缓存命中时显著变快）。
- 可选产物用 `load_optional`：不存在时返回 None，看板在**不同产出组合下都能起**（如只跑到 rfm 也能开看板看两页）。

## 四、测试与多数据支持

- `RETAILINSIGHT_MARTS` 环境变量重定向产物目录——两个用途：
  1. **AppTest 自动化测试**隔离（`tests/reporting/test_dashboard_apptest.py`，不去读写仓库真实产物）；
  2. 「换一份数据看看」（不同 scale / 不同 seed 的产物对比）。
- 看板端到端用 Streamlit 官方 `AppTest` 框架跑：页面渲染、筛选联动、下钻路径均有断言。

## 五、设计约束（刻意不做）

- 不写回：看板无编辑、无口径配置——改口径必须改 `features/` 重跑，防止「看板一套口径、报告一套口径」。
- 无鉴权/多用户：单机作品集定位。
- 不引重型前端：Streamlit + plotly 两个依赖封顶。

## 六、边界与已知缺口

1. 大数据量散点的渲染靠 plotly 浏览器端，36,000 点流畅；百万级需改采样或聚合层（当前规模不需要）。
2. 缓存 ttl 3600s 固定，重跑流水线后需手动清缓存或等待过期（无产物指纹失效机制）。
3. 无移动端适配（`layout="wide"` 桌面优先）。

## 维护触发

新增 mart 产物 → 评估进哪个页面 + `load_optional`；改交互 → 同步 `test_dashboard_apptest.py`。
