# RetailInsight 能力全景

> 对应域：全部（D1~D9）。关键数字一律引用 `README.md` 关键数字表，本篇不重复写值。

## 〇、摘要

RetailInsight 是一个**数据分析作品集项目**：以「悦鲜生活超市」为虚构业务背景，从合成数据生成开始，走完「清洗 → 分群 → 建模 → 决策建议」的完整闭环。它的能力设计有一个贯穿始终的原则——**每个结论都要有可验证的证据**：可验证性不是靠真实数据（合规上拿不到），而是靠**生成器埋点**（先验人群、强关联组合、脏数据）与**双实现互证**（pandas vs DuckDB SQL、简化法 vs BG/NBD、LR 基线 vs 主模型）。

一句话：**这不是「跑几个模型出几张图」的脚本集合，而是一条有验收线、有对照组、有降级路径的分析流水线。**

## 一、能力域地图

```
gen ──► etl ──► rfm ──► cluster ──► rules ──► rules_sku ──► rules_store
                 │         │                                    │
                 ▼         ▼                                    ▼
              churn ──► profile ──► warehouse ──► reports ──► report ──► cards ──► segment_compare
                                                                                    （dashboard 单独启动）
```

- 离线批处理：14 个 stage（`make all` 一键串联），全部产物落盘 `data/` 与 `reports/`。
- 在线交互：Streamlit 看板 4 页，只读 `data/marts/`，不重算指标。
- 验证资产：先验人群埋点（8 类）、购物篮埋点（4 组）、脏数据注入（5 类）、SQL 自证、时间外回测 ×2（流失 + CLV）。

## 二、逐域能力清单

### D1 数据生成（`scripts/generate_synthetic.py`）

| 能力 | 状态 | 入口 / 证据 |
|---|---|---|
| 全向量化 numpy 生成 | ✅ | scale=1（12 万会员 / 约 130 万交易）秒级完成 |
| 8 类先验人群埋点 | ✅ | 行为差异可验证聚类有效性（ARI 择优的真值来源） |
| 4 组购物篮强关联埋点 | ✅ | 洗发水→护发素等，验证规则挖掘回收率（4/4 全回收） |
| 脏数据注入（5 类） | ✅ | 重复行 0.5% / 会员ID缺失 3% / 退货负金额 1% / 品类别名 2% / 逻辑冲突 0.5%（含 1,511 行时间乱序） |
| 城市档位 × 人群品类乘子矩阵 | ✅ | 门店级品类差异度实测 0.0502（最高 0.1244），落在真实商超 0.05~0.30 下沿 |
| 分块流式生成 | ✅ | `--chunk-size`，峰值内存 ≈ 单块；`chunk_size=0` 产物与历史基线字节级一致 |

### D4 建模（`retailinsight/models/`）

| 能力 | 状态 | 入口 |
|---|---|---|
| K-Means 聚类（三重定 K） | ✅ | `models/cluster.py`：肘部法 + 轮廓系数（≥0.35）+ 业务可解释性；多特征空间按 ARI 择优 |
| 神谕上界检验 | ✅ | 用生成器埋的 8 类人群算轮廓上界，回答「0.35 可达不可达」 |
| 三模型对比选型 | ✅ | `models/cluster_compare.py`：K-Means / GMM / DBSCAN，结论由规则化准则给出 |
| 流失预测（防泄漏） | ✅ | `models/churn.py`：观察窗 270 天 + 标签窗 90 天，滚动 4 期 cohort，三向时间切分 |
| 成本最优阈值 | ✅ | 验证集上按业务成本选切点（漏判 1 人 = 误触 8 人，与决策报告 S2 同口径） |

| CLV 双口径 + 回测 | ✅ | `models/clv_bgnbd.py`（主）+ `models/clv.py`（对照/降级），91 天时间外回测同台比较 |

## 三、项目独有能力索引（对照通用数据分析项目）

| 编号 | 能力 | 为什么少见 |
|---|---|---|
| F1 | 生成器埋点验证（人群 + 关联 + 脏数据） | 合成数据项目大多「生成即终点」，本项目把埋点当**验收真值**用 |
| F2 | 神谕上界检验 | 先回答「指标天花板在哪」，再谈调参 |
| F3 | 双实现互证（pandas vs DuckDB SQL） | 用第二实现自证口径正确，而非只写单测 |
| F4 | 报告数字代码回填 | 杜绝「报告 35,576 / 实际 35,612」式漂移 |
| F5 | 成本最优阈值与业务报告同口径 | 阈值不是 Youden 指数，而是「漏判 1 = 误触 8」的决策口径 |
| F6 | 三模型规则化选型 | 结论由预设准则给出，不靠人工挑好看的结果 |
| F7 | 显式降级 + 留痕 | 降级不是静默兜底，产物里能查到哪次跑用了哪条路径 |
| F8 | 压测失败也出结论 | 爆内存的 stage 与规模写进性能报告，作为容量边界信息 |

## 五、状态汇总

- **已验收达标**：聚类轮廓（0.4165 ≥ 0.35）、流失 AUC 增益（+0.0305 ≥ +0.03）、看板首屏（0.51s < 3s）、覆盖率（82.78% ≥ 60%）、规则回收率（4/4）。
- **诚实标注未达标**：LightGBM 对照增益 +0.0184 < +0.03 —— 经 6 组敏感性实验确认为当前数据窗口的天花板，**如实写入报告而非继续调参**。
- **仅合成数据验证**：CLV 回测、品类差异度等结论的参数会随真实数据重估，文档均已标注。

## 六、边界与已知缺口

1. **合成数据外推边界**：门店级品类差异度 0.0502 落在真实区间下沿；客群级品类偏好仍是「弱差异」（0.0002~0.0095）。S8 门店差异化建议方向可验证、量级偏保守。
2. **无真实认证 / 多用户**：看板与 CLI 均为单机单用户形态，无权限、无多租户。
3. **无调度与增量**：stage 全量重跑，无 Airflow/cron 编排与增量 ETL（规模上单机足够）。
4. **毛利率是假设值**：CLV 取 30%（行业常见 25%~35%），已在报告标注。
5. **看板只读**：不支持在看板里改口径或写回，口径变更必须改 `features/` 重跑。
