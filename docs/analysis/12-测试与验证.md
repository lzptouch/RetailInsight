> 对应域：D9（工程基础 · 质量腿）。对应 Kquery 的「12-测试与验证」。关键数字见 `README.md` 关键数字表。

## 〇、摘要

**200 个用例 / 覆盖率 82.78% / ruff 全绿**。测试体系的特点是「**守卫测试**」：每一次重大修复（v3.2/v3.3/v3.4/v3.6）都沉淀为一个防回归测试文件，让修过的缺陷永不复活。

## 二、关键测试设计

### 2.1 防泄漏测试（`tests/models/test_leakage.py`）

流失模型的核心风险是时间泄漏。该测试构造「如果特征含标签窗信息就会异常高分」的探针，验证特征/标签的物理隔离有效——**测的不是模型准，而是模型不可能作弊**。

### 2.2 看板端到端（`tests/reporting/test_dashboard_apptest.py`）

Streamlit 官方 `AppTest` 框架：起真实脚本、模拟交互，断言页面渲染与筛选联动；用 `RETAILINSIGHT_MARTS` 指向夹具产物，不碰仓库真实数据。

## 三、门禁体系（`Makefile` + `pyproject.toml`）

| 门禁 | 命令 | 阈值 |
|---|---|---|
| 测试 + 覆盖率 | `make test` | 200 用例全过 + **覆盖率 ≥60%**（`--cov-fail-under=60`） |
| lint | `make lint` | ruff 严格规则集（E/F/I/UP/B/SIM）全绿 |

**刻意的取舍**：
- 覆盖率门禁**不放在 `addopts`**：放在 addopts 会让 `pytest tests/xxx.py` 单文件运行必然因「总覆盖率 0%」判红（v3.6 修）；门禁只在 `make test`/`make cov` 的全量运行生效。
- `ruff format` 是**建议项**不进 lint 门禁：仓库尚未统一格式化（基线 50/56 文件会被重排），避免门禁长期红灯；需要时 `make format` 单独执行。

## 五、覆盖现状与缺口

1. **82.78% 覆盖率**下未覆盖的主要是：CLI 的 dashboard 分支（交互阻塞）、部分降级路径（本机装了 lifetimes/lightgbm 时 fallback 分支不走）。
2. 无性能回归门禁：压测靠手动跑 `exp_scale5.py`，未进 `make test`。
3. 无快照测试：13 张图的视觉回归未自动化（图表正确性靠数据断言而非像素比对）。
4. metrics json 的字段 schema 无契约测试（报告渲染器测试间接覆盖）。
