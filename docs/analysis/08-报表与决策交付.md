# 报表与决策交付

> 对应域：D6（决策交付）。对应 Kquery 的「08-安全与治理」位次，但本项目的「治理」是**数字口径治理**。关键数字见 `README.md` 关键数字表。

## 〇、摘要

交付层的核心矛盾：**报告里的数字会随数据重跑而漂移**。解法是把「写报告」变成「渲染报告」——模板里只留占位符，全部 KPI 与测算数字由代码从 `data/marts` 产物回填。加上 Excel、13 张图、画像卡片、差异论证，构成本项目的完整交付物矩阵。

## 一、决策建议报告（`reports/render_decision_report.py`）

### 1.1 为什么需要渲染器

手写的数字会漂移（实测曾出现「会员 35,576 / 实际 35,612」式失配）。渲染器把报告改为：**模板（`reports/templates/决策建议报告.md.tpl`）+ 从 marts 回填全部数字**，数字唯一来源是代码。

### 1.2 报告结构（`reports/决策建议报告.md`）

- 〇、执行摘要；一、关键发现；**二、改进建议 S1~S8（每条含量化测算：公式、假设、验证方式）**；三、落地路线图；四、模型与方法附注。
- S 系建议与模型的对应关系（示例）：S2 流失挽回 ↔ churn 成本阈值同口径；S5/S6 采购与陈列 ↔ 关联规则；S8 门店差异化 ↔ 分门店规则 + 品类差异度（局限已标注）。

### 1.3 测算纪律

每条建议必须给出：测算公式 → 假设（如毛利率 30%、挽回率区间）→ 验证方式（哪份 metrics json / 哪张 mart 可复核）。**建议不是观点，是可复核的算式**。

## 二、客群画像卡片（`reports/profile_cards.py`）

- 产出 `reports/客群画像.md`：8 个客群各一页，含规模 / GMV 贡献 / 消费能力 / 偏好品类与品牌 / 流失与 CLV / 触达建议。
- **触达建议由规则表驱动**（`ACTION_RULES`：客群 × 关键指标 → 建议，按优先级命中第一条）——不写死文案，客群规则变化时建议自动跟随，避免「建议与画像脱节」。
- 示例：流失风险客户 →「定向高面额券 + 专属客服回访 + 30 天内品类偏好推送（挽回优先于增量）」。

## 六、边界与已知缺口

1. 模板回填是字符串替换机制，无类型检查——模板占位符写错会以「缺数字」形式暴露，靠 `tests/reporting/test_report_renderer.py` 兜底。
2. 报告语言为中文固定文案，无多语言/多受众版本。
3. Excel 无图表内嵌（纯数据 sheet），图表以 png 单独分发。

## 维护触发

新增建议条目 → 模板 + 回填字段 + S 编号同步；新增 mart 产物 → 评估是否进报告回填与画像卡片规则表。
