# 数据生成与 ETL 链路

> 对应域：D1（数据生成）、D2（ETL 与质量）。对应 Kquery 的「06-入库与解析链路」。关键数字见 `README.md` 关键数字表。

## 〇、摘要

离线链的两段：**生成**（`scripts/generate_synthetic.py`，raw 层）与**ETL**（`retailinsight/etl/pipeline.py`，raw → interim + 质量报告）。这条链路的设计核心是「**脏数据是故意注入的，清洗是必须证明的**」——生成器按固定比例注入 5 类脏数据，ETL 逐规则清洗并产出清洗前后对比的质量报告，每一步都可验收。

## 一、合成数据生成器（D1）

### 1.1 为什么用合成数据

- 合规：不含任何真实个人信息，可公开进作品集与 GitHub。
- 可验证：埋点就是真值——聚类对不对（先验人群 ARI）、规则全不全（预埋组合回收率）、清洗净不净（脏数据注入率已知），都能量化验收。
- v3.5 已删除开源数据集下载器与字段映射层：它不进主链路（三源 sha256 全 None），且英美第三方数据会破坏「中国商超 + 先验人群」的可验证性。

### 1.2 埋点设计（生成器的「考题」）

| 埋点 | 内容 | 验证对象 |
|---|---|---|
| 8 类先验人群 | `_persona` 字段，行为模式各异 | 聚类特征空间按 ARI 择优、神谕上界检验 |
| 4 组购物篮强关联 | `ANCHOR_COMBOS`（洗发水→护发素、火锅底料→牛羊肉等） | 关联规则回收率（实测 4/4 全回收） |
| 脏数据 5 类 | 重复行 0.5% / 会员ID缺失 3% / 退货负金额 1% / 品类别名 2% / 逻辑冲突 0.5% | ETL 清洗规则 + 质量报告 |
| 城市档位 × 人群品类乘子矩阵 | 门店级与人群级品类结构差异 | S8 门店差异化建议的方向验证 |

### 1.3 分块流式生成

- `--chunk-size N`：按会员分块，逐块生成 + `append_partitioned` 追加落盘，**峰值内存 ≈ 单块**。
- 实测：20 万会员 / 1,200 万明细 5.2s 完成，峰值内存 ≈1.0GB、落盘 108MB。
- `chunk_size=0` 走原路径，产物与历史基线**字节级一致**（兼容性有测试守卫）。

### 1.4 已知边界

- 原始数据范围 2010-01 ~ 2022-07，其中 1,511 行是故意注入的时间乱序脏数据（全部标 `is_logic_error=True` 剔除）；**有效分析窗口 2020-01 ~ 2022-07**（31 个月，非完整年度：1~7 月三年可比、8~12 月两年可比，同比口径需注意）。
- 门店级品类差异度 0.0502（最高 0.1244）落在真实商超 0.05~0.30 的**下沿**；客群级品类偏好 0.0002~0.0095（受 ARI≈0.13 稀释）仍属「弱差异」——两处口径与局限均写入了决策报告与画像卡片。

## 二、ETL 流水线（D2）

### 2.1 处理顺序（`etl/pipeline.run_etl()`）

raw 读取 → 逐规则清洗（`etl/clean.py`）→ dtype 优化（`optimize_dtypes`）→ 分区落盘（`write_partitioned`，明细按 `txn_month` hive 分区）→ 质量报告（`etl/quality.py` + `quality_html.py`）。

### 2.2 清洗规则（每条独立函数、可单测）

| 规则 | 函数 | 处理 |
|---|---|---|
| 品类别名归一 | `normalize_category` | 按 `CATEGORY_ALIASES` 替换，返回修正条数 |
| 交易去重 | `dedup_transactions` | 按 `txn_id` 保留首条 |
| 退货标记 | `flag_returns` | `amount<0` → `is_return=True`，不删除、净额自然为负 |
| 缺失会员处理 | `handle_missing_members` | 哨兵 `-1` 归为非会员（`member_type`），不丢行 |
| 逻辑异常剔除 | （时间乱序等） | 标 `is_logic_error=True`，分析侧剔除 |

### 2.3 业务口径的缺失判定（`etl/quality.py`）

- ID 列缺失**不能只判 isna**：生成器把「会员ID缺失」写成 `member_id=-1` 哨兵（NaN 会在 dtype 优化与 groupby 中被静默吞掉），`_missing_mask` 对 `*_id` 整数列同时判 `== -1`。
- 字符串列统一 strip+lower 后比对哨兵集合（`""/"nan"/"none"/"null"/"unknown"/"未知"/"未填"`）。
- 这是 v3.4 修过的真缺陷：只判 NaN 时质量报告的缺失率一节永远是空表。

### 2.4 数据质量报告

三件套：`reports/数据质量报告.md`（人读）+ `.json`（程序读）+ `.html`（自包含，可单独分发）。内容为清洗前后对比（行数、缺失率、各规则修正条数）。

## 三、状态机视角

```
generate_synthetic ──► data/raw/ ──► clean(逐规则) ──► optimize_dtypes
       │                                                    │
   埋点/脏数据注入                                            ▼
                                            data/interim/（明细按月分区）
                                                    │
                                                    ▼
                                          质量报告(md+json+html)
```

## 四、边界与已知缺口

1. 全量重跑，无增量 ETL（规模上单机 2.5 分钟可接受）。
2. 质量规则覆盖注入的 5 类脏数据；未覆盖的异常类型（如价格离群）只在报告呈现、不自动处理。
3. 生成器参数（规模、埋点强度）硬编码在 `io/schema.py` 与生成器常量里，无外部配置文件。
